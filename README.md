# 闭环管理废弃物回运责任服务

本项目提供极地科考站服务端应用共用的基础能力，用于登记科考机构、站点、操作者和结构化业务资料，并提供角色权限、请求幂等、SQLite 事务与哈希串联审计。具体的物流、样品、能源、医疗和许可业务可在这些边界上扩展自己的状态、规则和接口。

`waste_return_chain`（废弃物回运责任项目）建立在上述边界之上，解决年度撤站盘点中暴露的问题：**箱体总重量对得上，却无法证明每一类废油、废电池、受污染包装各自完成了许可、暂存、移交、接收和处置责任**。

## 责任链覆盖的环节

从产生地点到处置凭证，每个环节都是只增事件，旧事实不被改写：

1. **法规版本发布**：每版规则包含混装限制、各类期限（暂存、移交确认、接收签收）和责任人要求。
2. **产生地点登记**：按废弃物类别登记批次、危险特性、数量单位、封装方式和许可证号。
3. **封箱**：逐批次冻结不可变清单，并把**封箱时适用的整版法规快照复制进容器**；后续发布的新版本不改写旧箱。封箱校验混装矩阵、单位一致和封箱总量不超过登记（含冲销）数量。
4. **暂存**：入库冻结暂存期限与保管责任人，出库释放；暂存期间不得移交。
5. **跨营地移交 / 承运交接 / 目的地交付**：发起方与确认方必须不同，**责任只在对方确认后转移**。
6. **接收签收**：接收方按批次逐项核对在箱数量；数量不符只能冲销修正或拒绝。
7. **异常的冲销与重新分配**（一律新增事件，不回滚已完成责任）：
   - 容器破损 → 标记 `damaged`，冻结运输，必须拆箱重装到新箱；
   - 运输取消（承运在途）或目的地接收拒绝 → 发起 `return_transfer` 冲销回运，原移交记录保留为 `confirmed`；
   - 数量修正 → 追加正/负冲销事件，原始登记数量永不修改。
8. **拆箱重装**：旧箱→新箱按批次建立血缘边；余额清零的旧箱转为 `repacked` 保留，新箱重新冻结当前法规。
9. **处置凭证**：目的地按全部在箱组成开具凭证，容器转为 `closed`，责任关闭且不可再改。

## 双向可追溯

- **从来源追到去向**：`trace_lot` 返回批次的全部血缘边、冲销修正和处置凭证，给出 `in_circulation / partial / disposed` 结论。
- **从箱子反查组成**：`trace_container` 沿血缘边递归回溯（支持多代重装、多来源合并），即使箱子已关闭或已完全重装，也能列出它曾经包含的每个产生批次、许可和数量，同时给出暂存、移交、签收、凭证时间线与当前责任方。
- 血缘边在每一层数量守恒；`quantity_variance` 按批次比对登记（含冲销）、封箱、在途、已处置数量，`overdue_nodes` 给出逾期未确认移交、逾期暂存、目的地逾期未签收和破损未重装四类节点。

## 可靠性

- 所有写操作要求 `request_id`；相同请求编号 + 相同载荷的重复回调（含进程重启后）返回原始回执（`replayed=true`），不产生重复责任事件；相同编号不同载荷报冲突。
- 状态机校验位于幂等查找之后，因此状态已推进（已出库、已确认、已关闭）后的重放不会被误判为冲突。
- 双方确认、`BEGIN IMMEDIATE` 短事务、外键约束和哈希串联审计共同保证移交、核销与恢复的一致性。

## 目录

- src/polar_station_foundation/：领域模型、SQLite 存储、权限服务、审计链、HTTP 路由和离线验收（基础服务）。
- src/waste_return_chain/：废弃物回运责任项目的规则、表结构、责任服务、HTTP 路由与离线验收。
- tests/：基础规则与废弃物项目的服务、接口、端到端验收测试。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

    PYTHONPATH=src python3 -m unittest discover -s tests -v

## 构建检查

    python3 -m compileall -q src tests

## 离线验收

基础服务：

    PYTHONPATH=src python3 -m polar_station_foundation.acceptance

废弃物回运责任项目：

    PYTHONPATH=src python3 -m waste_return_chain.acceptance

验收命令在临时 SQLite 数据库中走通产生登记、封箱冻结、暂存、双方确认的跨营地/承运/目的地移交、接收拒收冲销回运、破损重装、处置凭证关闭，以及进程恢复后的继续办理与幂等核销，核对双向追溯、数量差异与审计链，成功时输出一行 status 为 ok 的 JSON 并以退出码 0 结束。

## HTTP 服务

基础服务：

    PYTHONPATH=src python3 -m polar_station_foundation.api --database polar_station.sqlite3 --host 127.0.0.1 --port 8080

废弃物回运责任项目（同一库同时包含基础表与 `wr_` 前缀业务表）：

    PYTHONPATH=src python3 -m waste_return_chain.api --database polar_station.sqlite3 --host 127.0.0.1 --port 8080

健康检查使用 GET /health。写入接口通过 X-Actor-Id 标识操作者，所有废弃物写操作位于 `/waste/...` 路径并要求 request_id；服务重启后 SQLite 中的业务状态、血缘与审计历史继续保留。
